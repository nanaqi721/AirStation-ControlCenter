# Modbus RTU 通信实施指南

## 1. 文档用途

本文是项目中 Modbus RTU 通信实现的单一事实来源。涉及 NModbus 主站/从站、虚拟串口、Modbus Slave、点位地址、轮询、读写、超时、重连或通信诊断时，先读取本文。

空压机状态机、压力变化、储气罐、过滤器和辅机行为由 [VIRTUAL_AIR_COMPRESSOR_SIMULATION.md](VIRTUAL_AIR_COMPRESSOR_SIMULATION.md) 维护，本文不重复描述设备物理模型。

## 2. 固定技术选择

- 上位机：`.NET 7` WinForms。
- 协议库：NModbus 与 NModbus.Serial。
- 串口：System.IO.Ports。
- 协议：Modbus RTU 主站。
- 仿真从站：前期使用 Modbus Slave 软件，后期使用独立 C# 模拟器中的 NModbus RTU 从站。
- 协议职责：NModbus 负责 RTU 帧、CRC 和功能码；项目负责点表、数据类型、字节序、缩放、数据质量、调度和业务含义。

## 3. 通信实施路线

通信按下面两个阶段推进，阶段一验证通过后再进入阶段二。

### 第一阶段：Modbus Slave 软件手工验证

```text
AirCompressor.ControlCenter.WinForms
NModbus RTU 主站，打开 COM8
                 │
             虚拟串口对
                 │
Modbus Slave 软件
RTU 从站，打开 COM9
```

目标是用最少变量验证完整的 RTU 通信链路，不模拟空压机自动运行规律。

实施步骤：

1. 准备一对虚拟串口，例如 COM8 与 COM9。
2. 上位机使用 COM8，Modbus Slave 使用 COM9；任何时刻每个端口只由一个程序打开。
3. 两端统一波特率、数据位、校验位、停止位和从站地址。
4. 在 Modbus Slave 中建立一个最小连续数据区。
5. 上位机先读取一个寄存器，再扩展到连续批量读取。
6. 手工修改压力、温度、状态等原始值，确认上位机在下一轮轮询后更新。
7. 测试允许的单点/多点写入，并执行写后回读。
8. 主动关闭 Modbus Slave 或串口，验证超时、离线状态和自动重连。
9. 恢复从站，验证上位机无需重启即可重新获得 Good 数据。

建议的开发参数仅作样例：

```text
主站端口：COM8
从站端口：COM9
波特率：9600
数据位：8
校验位：None
停止位：1
从站地址：1
```

完成标准：

- 连续运行时读取稳定且界面不阻塞。
- 手工修改值后，显示值与缩放规则一致。
- 允许的写入可以回读确认，非法写入有明确结果。
- 断开后进入 Offline，恢复后自动重连并回到 Good。
- 日志能定位端口、从站、功能码、起始偏移、数量、耗时和异常类型。

### 第二阶段：独立代码模拟器

```text
AirCompressor.ControlCenter.WinForms
NModbus RTU 主站，打开 COM8
                 │
             虚拟串口对
                 │
AirCompressor.ControlCenter.Simulator
NModbus RTU 从站，打开 COM9
```

目标是让独立 C# 程序同时承担“空压站行为模型”和“Modbus RTU 从站”，替代人工修改寄存器。

实施步骤：

1. 在用户明确授权写入后创建 `AirCompressor.ControlCenter.Simulator` 项目。
2. 使用与第一阶段完全相同的串口参数和最小点表，先启动一个从站地址 1。
3. 使用 NModbus 创建 RTU 从站网络、从站实例和数据存储区。
4. 首先填入固定寄存器值，确认第一阶段的所有读写测试仍然通过。
5. 接入仿真引擎，由状态机定时更新寄存器和状态位。
6. 将主站写入转换为启动、停止、复位或参数设定命令，不让通信层直接操纵业务状态。
7. 写入处理完成后更新数据区，让上位机执行回读确认。
8. 增加暂停响应、关闭端口、拒绝写入、返回异常值等故障注入入口。
9. 验证模拟器或上位机任意一方重启后能够重新建立通信。

完成标准：

- 上位机不修改业务/UI代码即可从 Modbus Slave 切换到独立模拟器。
- 模拟器自动变化的数据能被稳定轮询、解析和归档。
- 控制命令只执行一次，并有命令、结果和回读记录。
- 超时、断线、重连和异常响应均可重复测试。
- 仿真场景的完成标准满足后，才把通信阶段标记为已验证。

## 4. 上位机通信模块边界

UI 不直接持有 SerialPort 或 NModbus 对象。推荐调用关系：

```text
WinForms UI
    ↓ 订阅快照、提交命令
Application Services
    ↓
IPlantGateway
    ↓
NModbusPlantGateway
    ├── SerialConnectionManager
    ├── PollingScheduler
    ├── RegisterDecoder
    ├── WriteCommandQueue
    └── CommunicationDiagnostics
```

职责：

- `SerialConnectionManager`：打开、关闭、取消、重连和释放端口。
- `PollingScheduler`：按轮询组调度读取并合并连续地址。
- `RegisterDecoder`：处理类型、符号、字节序、字序、比例和偏移。
- `WriteCommandQueue`：串行执行写入、限流、超时和回读。
- `CommunicationDiagnostics`：记录最近成功时间、耗时、超时、异常和重连次数。

完成标准：更换 UI 页面或仿真从站不需要复制串口、轮询和解析代码。

## 5. 点表与地址规则

第一阶段的权威点表是 [空压站PLC学习用Modbus变量表.xlsx](../空压站PLC学习用Modbus变量表.xlsx)。配置 Modbus Slave、实现 NModbus 主站、建立独立模拟器或编写标签映射时，统一使用其中的功能码、协议偏移、数据类型、长度、比例、读写权限和轮询组。需要调整地址时，先修改并版本化该点表，再同步实现；代码和其他文档不另建一套地址事实源。

该点表假定一个从站（Slave ID 1）代表整个空压站 PLC。它是学习与仿真用的项目自定义映射，不是任何品牌 PLC 或空压机的通用寄存器表。变量选择依据见 [VARIABLE_TABLE_RESEARCH.md](VARIABLE_TABLE_RESEARCH.md)；接入真实设备时，以厂商手册和现场确认点表替换。

点位至少定义：

```text
设备/从站、数据区、文档地址、协议偏移、数据类型、长度、字节序、字序、比例、偏移、单位、读写权限、轮询组、上下限
```

地址统一在点表加载阶段规范化。例如设备手册中的 `40001` 常对应协议偏移 `0`，但不同厂商可能使用不同规则。业务代码只使用已经规范化的协议偏移，不在各处临时加减 1。

启动前校验：

- 地址范围与数据区是否合法。
- 32 位或 64 位数据占用的寄存器是否重叠。
- 同一设备和数据区是否存在冲突地址。
- 功能码与读写属性是否一致。
- 缩放、范围和单位是否完整。

完成标准：错误点表在开始轮询前给出可定位的校验错误。

## 6. 轮询与串口规则

- 同一个串口同一时刻只执行一个 Modbus 请求。
- 优先把相同从站、相同数据区的连续地址合并读取。
- 为不同变化速度设置轮询组，避免所有点都使用最快周期。
- UI刷新频率可以低于采集频率，使用不可变快照或事件发布数据。
- 写入与读取使用同一调度入口，防止多个线程同时操作串口。
- 所有后台操作支持取消，关闭程序时先停止调度再释放串口。

完成标准：并发读取、写入和关闭程序时没有端口占用、交叉响应或 UI 卡死。

## 7. 超时、重试与重连

一次请求失败后：

1. 记录请求上下文和异常。
2. 将相关点位更新为 Bad 或 Stale，不保留为无条件 Good。
3. 在有限次数内按策略重试。
4. 连续失败达到阈值后关闭端口并进入 Offline。
5. 使用退避间隔尝试重新打开端口。
6. 成功读取有效数据后恢复 Good，并记录恢复事件。

重连循环不得阻塞 UI，也不能无限高频打开串口。

完成标准：拔掉/关闭虚拟串口后应用保持响应；恢复端口后能够自动通信；状态变化和原因可追踪。

## 8. 读取与写入安全

- 只允许点表中标记为可写的点位进入写队列。
- 写入前执行类型、范围、权限和设备状态校验。
- 启停、复位和重要参数需要二次确认。
- 写入完成后回读确认；返回成功不等于设备最终状态已经改变。
- 每次控制记录用户、时间、点位、原值、目标值、通信结果和回读结果。
- 急停、超压、超温等安全联锁由 PLC/本地控制器实现，上位机不能作为唯一保护层。

完成标准：越权、越界、只读点和状态不允许的命令不会发到设备；合法命令有完整审计。

## 9. 数据质量

统一使用：

- `Good`：最近一次读取成功且仍在有效期内。
- `Stale`：曾经读取成功，但数据已经超过有效期。
- `Bad`：收到无法解析、越界或协议异常的数据。
- `Offline`：连接不可用或连续请求失败达到阈值。

UI 显示数据值的同时必须显示质量；历史归档保存质量或明确过滤策略。

完成标准：通信中断时界面不会继续把旧值显示为正常实时值。

## 10. 验证清单

| 场景 | 预期结果 |
|---|---|
| 正确参数读取 | 获得 Good 数据，缩放正确 |
| 地址偏移错误 | 明确错误或异常值，能通过诊断定位 |
| 从站地址错误 | 超时并进入相应质量状态 |
| 手工修改寄存器 | 下一轮轮询显示新值 |
| 合法参数写入 | 写入成功且回读一致 |
| 越界或只读写入 | 本地拒绝，不发送请求 |
| 关闭从站 | UI保持响应，数据变为 Stale/Offline |
| 恢复从站 | 自动重连，读取成功后恢复 Good |
| 高频点击控制 | 写队列限流，命令不重复并发 |
| 关闭应用 | 后台任务取消，串口正常释放 |

每个场景记录配置、点表版本、操作、预期、实际结果和日志位置。全部适用场景通过后，通信阶段才能标记为已验证。

## 11. 状态记录规则

- 文档创建只表示通信路线已设计，不表示通信代码已实现。
- Modbus Slave 能读取一个值不等于第一阶段完成，必须满足该阶段全部完成标准。
- 独立模拟器能启动不等于第二阶段完成，必须验证动态读写、异常和恢复。
- 每次实现后更新 [PROJECT_STATUS.md](PROJECT_STATUS.md)，记录修改文件、串口参数、点表版本、验证场景、结果和遗留问题。
